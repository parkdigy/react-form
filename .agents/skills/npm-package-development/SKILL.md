# npm 패키지 코딩 절차

먼저 [저장소 지침](../../../AGENTS.md)과 작업에 관련된 소스·설정을 읽고 `git status --short`로 기존 변경을 확인한다. 구조 탐색이 필요하면 [프로젝트 구조](../../../docs/agents/project.md)를 참고한다.

## 영향 분석과 구현

- 공개 API는 `src/index.ts`와 하위 배럴을 따라 확인한다. 변경된 타입이나 사용법은 예제와 README에도 반영한다.
- 폼 값이나 이벤트 동작은 `PForm`, `PFormContext`, 입력 컴포넌트의 등록·해제, 검증, 사용자 변경 및 제출 흐름을 함께 추적한다. 검색 변경은 `PSearch`와 예제의 검색 화면도 확인한다.
- `.private` 접미사 디렉터리와 `.private.d.ts`는 Rollup에서 제거한다. 공개 선언이 제거된 타입을 참조하지 않는지 빌드 결과와 소비자 타입 검사로 확인한다. `src/@private/` 전체가 이 규칙으로 제거되는 것은 아니다.
- 예제는 `../src`를 직접 사용하며 `@comp`, `@ccomp`, `@common` 별칭을 TypeScript와 Rspack이 공유한다. 예제 성공만으로 배포 패키지의 소비 호환성을 판단하지 않는다.
- 의존성을 변경할 때는 루트와 예제의 사용처, peer 범위와 Node 버전 및 설치 트리를 확인한다. 특히 React 중복과 `@mui/x-date-pickers`의 peer 7.x / 개발 8.x 차이를 살핀다. 잠금 파일이 Git 제외 대상이므로 실제 설치에 사용한 옵션과 파일을 기록한다.

## 검증과 보고

[AGENTS.md](../../../AGENTS.md)의 타입·lint·빌드 지침을 따르고 변경에 맞는 테스트를 실행한다. 현재 Jest는 `.tsx` 변환과 DOM 환경이 없고 `test` 스크립트도 없으므로 컴포넌트 테스트를 추가할 때 실행 환경과 명령을 함께 마련한다.

생성물이 추적되므로 빌드 전에 기존 상태와 정리·복사 대상을 확인한다. 배포 경로나 모듈 형식 변경은 패키징 후 별도 소비 환경에서 import, require, 타입을 검사한다. Watchman 실패, 번들 경고, 미검증 브라우저 동작 등은 실제 결과와 구분해 보고한다.

여러 세션에 걸치거나 인계가 필요한 작업에는 [작업 기록 양식](templates/task.md)을 `_workspace/<작업명>/task.md`에 복사해 사용한다. 완료 전 diff를 검토해 기존 변경과 생성물이 의도대로 보존됐는지 확인한다.
